🏦 Sistema Bancario REST API - Documentación Integral (TP2)Aplicación backend desarrollada en Spring Boot para la gestión integral de un sistema bancario, estructurada bajo una arquitectura modular por capas, persistencia avanzada con Spring Data JPA, y control transaccional estricto.📐 Explicación de las Áreas del Proyecto (Trabajo Práctico)El proyecto está diseñado bajo el patrón de arquitectura en capas, separando responsabilidades para facilitar el mantenimiento, la escalabilidad y las pruebas:1. Capa de Dominio (model)Concepto: Representa las entidades de la base de datos y las reglas del modelo de negocio orientado a objetos.Implementación:Utiliza superclases de auditoría (Auditable), herencia mapeada con la estrategia JOINED para las cuentas financieras (CuentaFinanciera, CajaDeAhorro, CuentaCorriente), y relaciones relacionales complejas como @ManyToMany entre clientes y cuentas.   2. Capa de Acceso a Datos (repository)Concepto: Actúa como el puente entre la aplicación y la base de datos relacional (MySQL) mediante Spring Data JPA.Implementación:Interfaces como ClienteRepository, CuentaFinancieraRepository y TransaccionRepository extienden de JpaRepository, permitiendo realizar operaciones CRUD automáticas y consultas derivadas personalizadas por atributos específicos (CBU, CUIL, estado).   3. Capa de Servicios (service)Concepto: Concentra la lógica de negocio de la aplicación, validaciones operativas y la gestión de transacciones atómicas.Implementación:Clases como ClienteServiceImpl, CuentaFinancieraServiceImpl y TransacicionServiceImpl procesan reglas críticas (como control de saldos y registros dobles de transferencias) bajo la anotación @Transactional para garantizar la integridad de los datos.   4. Capa de Controladores (controller)Concepto: Expone la interfaz de la API REST hacia el exterior, recibiendo las peticiones HTTP de los clientes.Implementación:Controladores mapeados bajo /api/v1 (ClienteController, CuentaController, TransactionController) que procesan los JSON de entrada, aplican validaciones con @Valid y devuelven respuestas HTTP estructuradas (ResponseEntity).   5. Objetos de Transferencia de Datos (dto)Concepto: Estructuras planas utilizadas para transportar únicamente los datos necesarios entre el cliente y el servidor, desacoplando las entidades de la base de datos.Implementación:DTOs de petición y respuesta (ClienteRequestDto, CuentaResponseDto, TransferenciaRequestDto, etc.) validados mediante anotaciones de jakarta.validation (@NotBlank, @Email, @Positive).   💻 Concepto de Comandos Utilizados en el DesarrolloPara compilar, gestionar dependencias y controlar las versiones del proyecto durante el desarrollo de los trabajos prácticos, se emplean los siguientes comandos fundamentales:Comandos de Maven (mvn)Maven es el gestor de proyectos y dependencias utilizado en Java.mvn spring-boot:runConcepto: Compila el código fuente del proyecto y arranca la aplicación de Spring Boot integrando un servidor web embebido (como Tomcat), permitiendo probar los endpoints de la API de forma local.mvn clean installConcepto: El comando clean elimina el directorio target/ con los archivos compilados anteriores. El comando install compila el código, ejecuta las pruebas unitarias (si las hay) y empaqueta la aplicación en un archivo .jar, guardándolo en el repositorio local de Maven.
